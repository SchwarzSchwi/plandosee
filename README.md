# 플랜두씨 다이어리

Supabase PostgreSQL + Vercel Serverless API + 정적 HTML/JavaScript. 데이터는 브라우저 저장소가 아닌 서버 DB에 보존됩니다.

## 설치·업그레이드

1. 새 DB는 `supabase/schema.sql` 실행. **기존 DB는 대신** `supabase/migrations/001_t06.sql`을 한 번 실행합니다. 둘 다 실행하지 마세요. 마이그레이션 전에 백업하세요. 기존 값이 새 제약조건(음수 시간, 잘못된 우선순위·상태·기간)에 위배되면 트랜잭션 전체가 실패하므로 먼저 해당 값을 확인하세요.
2. 예시 화면이 필요하면 `supabase/seed.sql` 실행. 고정 ID로 중복 삽입되지 않는 **가상 데모**(계획 1, 할 일 5, 작업 실행 3, 완료 이벤트 1)입니다. 사용자의 실제 활동을 가장하지 않습니다. C78~C80의 실제 사용자 계획·활동 증빙은 사용자가 직접 입력해야 합니다.
3. `.env.example`을 참고해 Vercel 서버 환경 변수에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 등록. 기존 `SUPABASE_SERVICE_ROLE_KEY`도 호환됩니다. 키는 서버 전용이며 `VITE_`/`NEXT_PUBLIC_` 접두어를 붙이지 마세요.
4. `npm install`, `npm test`. 로컬 전체 앱은 Vercel 인증·프로젝트 연결 후 `npm run dev`. `.env.local`에 서버 환경 변수를 설정할 수 있습니다. Vercel 배포의 정적 출력은 `public`이며 `/api`만 DB에 접근합니다.

## 데이터 구조와 API

| 모델 | DB 테이블 | 보존 값 |
| --- | --- | --- |
| Plan | `plans` | ID, 제목, 기간(시작/종료일), 우선순위, 성공 기준, 예상 분, 설명 |
| PlanRevision | `plan_versions` | 원래 계획 ID, 변경 전 **전체** JSON 스냅샷, 생성시각 |
| Todo | `tasks` | 계획 ID, 제목/내용, 마감일, 우선순위, 태그 배열, 예상 분, 현재 상태, 삭제시각 |
| ExecutionLog | `execution_logs` | 할 일 ID, 시작/종료시각, 실제 분, 막힘 이유, 종류(`work`/`completion`) |
| Retrospective | `reviews` | 계획 ID, 고칠 점 한 건, 생성시각. 숫자는 현재 DB 기록으로 계산 |

- 날짜는 `YYYY-MM-DD`, 시각은 타임존을 포함한 ISO 8601, 시간 단위는 항상 **분**입니다. 실행 입력 시각은 서울시간으로 해석하여 전송합니다. 실제 분은 서버에서 `(끝−시작)/60000`을 반올림하며 계획/할 일의 예상 값은 변경하지 않습니다.
- `/api?table=...`: GET 조회, POST 생성, PATCH 계획/할 일 수정, DELETE 할 일 논리 삭제. 서버가 허용 필드·형식·범위를 검사하며 이력은 직접 수정할 수 없습니다.
- 완료는 `PATCH /api?table=tasks&id=...`의 `{"status":"done"}`, 되돌리기는 `{"status":"progress"}`입니다. DB 트리거와 부분 UNIQUE 인덱스가 동시 요청에도 할 일당 최초 완료 이벤트를 **한 건만** 보존합니다. 이벤트는 0분이며 재개·재완료해도 추가되지 않습니다. 완료 수는 이벤트 개수가 아닌 현재 상태로 계산합니다.
- 계획 수정과 이전 값 스냅샷은 동일 DB 트랜잭션입니다. 값이 바뀌지 않은 저장은 이력을 추가하지 않습니다.
- `POST /api?action=carry-forward`에 `plan_id`, `improvement`를 보내면 돌아보기 저장과 다음 계획 생성이 함께 성공하거나 함께 취소됩니다. 다음 계획의 설명에 고칠 점 한 건이 들어가고, 기존 계획 필드를 복사한 뒤 수정 화면에서 새 기간 등을 설정할 수 있습니다.
- 삭제된 할 일과 실행 기록은 내보내기에는 보존되지만 화면 집계에서는 제외합니다.

## 돌아보기·검색 규칙

집계와 검색/필터/정렬 함수는 UI와 분리된 `public/model.js`에 있습니다.

- 계획 수: 선택한 계획에 속한 미삭제 할 일 수.
- 완료 수: 그중 **현재** `done`인 수.
- 지연 수: 미완료이면서 마감일이 `Asia/Seoul` 기준 오늘보다 앞선 수(오늘 마감·마감일 없음 제외).
- 막힘 수: 비어 있지 않은 막힘 이유가 작업 실행 기록에 하나라도 있는 할 일 수(여러 이유도 한 번만).
- 예상: 대상 할 일 예상 분의 합. 실제: 대상 할 일의 작업 실행 분 합. 차이: 실제−예상. 없는 값은 0. 최초 완료 이벤트는 0분 관리 기록이며 작업 합계에서 제외됩니다.
- 모든 집계 숫자를 누르면 해당 할 일/실행 기록을 확인합니다.
- 제목·내용·태그 검색과 상태/지연 필터를 함께 적용합니다. 마감일 오름차순(없으면 마지막) → 우선순위 높음순 → 제목 한국어순 → ID순으로 정렬합니다.

## 전체 내보내기·복원

`전체 내보내기`는 단일 DB 스냅샷에서 모든 엔터티(삭제 표시 포함)를 제한 없이 읽은 JSON 파일 하나입니다. 화면 로딩도 같은 API를 사용해 새로고침 시 저장된 ID·날짜·값·분 단위를 그대로 조회합니다. 파일 가져오기 UI는 제공하지 않습니다.

```json
{
  "version": 1,
  "exported_at": "2026-10-27T00:00:00+00:00",
  "plans": [],
  "plan_versions": [],
  "tasks": [],
  "execution_logs": [],
  "reviews": []
}
```

## 보안과 운영 한계

첫 화면에는 다음 문구를 그대로 표시합니다:

> 지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요

- **API는 인증 없는 공개 읽기/쓰기입니다.** RLS와 서버 전용 키는 브라우저의 DB 직접 접근을 막지만 공개 API 이용자를 구분하지 않습니다. 민감정보를 넣지 마세요. 비공개 운영 전 인증/권한 검사·요청 제한을 추가해야 합니다.
- 사용자 문자열은 DOM 텍스트 노드/입력 값으로만 표시하며 `innerHTML`을 사용하지 않습니다. 스크립트 형태 문자열도 그대로 저장·표시됩니다. 배포 CSP는 외부/인라인 스크립트 실행을 차단합니다.
- DB 오류 원문과 서버 키는 응답·콘솔로 출력하지 않습니다. `.env*`, 의존성, Vercel 로컬 설정은 Git에서 제외합니다. 노출된 키가 있다면 파일 삭제만으로 해결되지 않으므로 즉시 폐기·교체하고 별도로 이력을 정리해야 합니다.
- 확인 가능한 로컬 Git 이력에서 주요 비밀키 패턴은 발견되지 않았으나, 원격 전체 이력·기존 배포 산출물까지 검사한 것은 아닙니다.
- 전체 JSON을 메모리에서 처리하므로 대량 데이터에서는 Vercel/Supabase 응답 크기·시간 제한에 도달할 수 있습니다.

## 검증

- `npm test`: Node 기본 테스트 러너로 API 입력·상태 요청·오류 비노출, 서울 자정 경계, 집계/0 기본값, 검색·필터·정렬 검증.
- PostgreSQL 서버 도구가 있으면 `npm test`가 임시 격리 DB에서 `test/database.sh`·`test/database.sql`도 실행합니다(도구가 없거나 root면 명시적으로 skip). 완료 중복·동시 요청·재개·재완료, 이력, 제약조건, 이월, 내보내기, 데모 데이터를 검사하며 임시 파일은 `/tmp`에서 정리합니다.
- 브라우저에서 모의 API로 경고문, 검색+필터, 집계 근거, 더블 클릭 요청 1회와 완료 수 +1, XSS 문자열 비실행을 확인했습니다.
- 실제 호스팅 Supabase/Vercel 연결은 자격증명 부재로 검증하지 못했습니다. 배포 전 스키마/마이그레이션 적용 및 서버 키 설정 후 새로고침·내보내기를 확인해야 합니다.
- 작업 시 운영 의존성 감사는 취약점 0건이었고 기존 Vercel 개발 도구 의존성에서는 29건이 보고됐습니다. 이 변경에서는 관련 없는 메이저 도구 업그레이드를 수행하지 않았습니다.
